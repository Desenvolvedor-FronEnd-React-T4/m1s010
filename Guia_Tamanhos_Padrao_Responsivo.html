1. A ideia mais importante: pixel CSS não é pixel da tela

Quando você escreve width: 375px, o navegador não está falando de pixels físicos do aparelho. Ele usa o pixel CSS (também chamado de pixel independente de dispositivo). Um iPhone 15 tem 1179 × 2556 pixels físicos, mas o navegador o enxerga como 393 × 852 pixels CSS. A razão entre os dois é o device pixel ratio (DPR), aqui igual a 3.

Pixel físico
O ponto real de luz na tela. Você quase nunca usa no CSS.
Pixel CSS
A unidade que o navegador usa para width, media queries e DevTools.
DPR
Quantos pixels físicos cabem em 1 pixel CSS (1x, 2x, 3x). Telas "retina" têm 2x ou mais.
Por isso as media queries usam a largura da viewport em pixels CSS. Um celular de tela 4K continua sendo "uns 400px" para o CSS. É o que faz o mesmo site funcionar em qualquer aparelho.

3. Breakpoints: onde o layout "quebra"

Breakpoint é a largura de tela em que o layout muda. Não existe padrão oficial da W3C: cada framework escolheu os seus, mas todos ficam bem próximos.

3.1 Conjunto recomendado para a nossa turma (mobile-first)

NomeMedia query (min-width)Em emAlvo
Base (sem media query)——Celular, de 320px em diante
Tablet@media (min-width: 768px)48emTablet em retrato
Notebook / Desktop@media (min-width: 1024px)64emNotebook e desktop
Tela grande (opcional)@media (min-width: 1440px)90emMonitores Full HD e maiores
Regra de ouro: use poucos breakpoints. Três "faixas" (celular, tablet, desktop) resolvem 90% dos casos. Se precisar de um quarto, é porque o conteúdo quebrou, e não porque existe um aparelho novo.

3.2 Comparação com os frameworks

FrameworkBreakpoints (min-width)
Bootstrap 5sm 576 · md 768 · lg 992 · xl 1200 · xxl 1400
Tailwind CSSsm 640 · md 768 · lg 1024 · xl 1280 · 2xl 1536
Material Designcompact <600 · medium 600–839 · expanded 840+
Nosso conjunto768 · 1024 · (1440)

O ponto em comum: 768px é praticamente universal para "tablet" e 1024px (ou 992px) para "desktop". Como usamos Bootstrap na quinta-feira (02/10), vale lembrar que lá o "desktop" começa em 992px.

3.3 Como escolher o valor do breakpoint

  • Não mire em aparelhos (iPhone X, Galaxy S9). Eles mudam todo ano.
  • Mire no conteúdo: arraste a janela até o layout ficar feio, e é ali que entra o breakpoint.
  • Prefira min-width (mobile-first) a max-width. Ver o guia de media queries.
  • Pode usar px ou em. Em em, o breakpoint respeita o zoom de fonte do usuário (1em = 16px no padrão do navegador).

Nunca use menos de 16px no corpo do texto em celular. Além de difícil de ler, o iOS dá zoom automático em campos de formulário (input) com fonte menor que 16px.

4.3 Regras que valem para qualquer tela

  • Unidade: use rem para fonte (respeita a configuração de acessibilidade do usuário). Evite px em font-size.
  • Comprimento da linha: entre 45 e 75 caracteres (≈ max-width: 65ch). Linhas muito longas cansam a leitura em telas grandes.
  • Contraste: mínimo 4,5:1 para texto normal (WCAG AA). Texto cinza claro sobre fundo branco reprova.
  • Fonte fluida: clamp(mín, ideal, máx) faz o título crescer suavemente sem media query. Exemplo: font-size: clamp(2rem, 5vw, 4rem);
  • No máximo 2 famílias de fonte por projeto (uma para títulos, outra para texto, ou uma só).

Como incluir (no <head> do HTML, antes do seu CSS):

<link rel="preconnect" href="https://fonts.googleapis.com">

Dica de desempenho: carregue só os pesos que você usa. Cada peso extra é mais um download. display=swap mostra o texto imediatamente com a fonte reserva enquanto a fonte real carrega.

5. Espaçamento

5.1 A grade de 8 pontos

Designers e desenvolvedores profissionais usam múltiplos de 8px (com 4px para ajustes finos) para margens, paddings e gaps. Isso deixa o layout consistente, e a decisão fica rápida: em vez de pensar "13px ou 15px?", você escolhe da escala.

TokenpxremUso típico
xs4px0.25remEspaço entre ícone e texto
sm8px0.5remEspaço entre itens pequenos, padding de badge
md16px1remPadding lateral no celular, gap entre cards, padding de botão
lg24px1.5remPadding interno de card, gap em tablet
xl32px2remMargem entre blocos de conteúdo
2xl48px3remEspaço entre seções no celular
3xl64px4remEspaço entre seções no desktop
4xl96px6remHero e grandes respiros no desktop

Dá para transformar essa escala em variáveis CSS, o que combina com o que vimos na Semana 07:

:root {
  --esp-xs: 0.25rem;  --esp-sm: 0.5rem;  --esp-md: 1rem;   --esp-lg: 1.5rem;
  --esp-xl: 2rem;     --esp-2xl: 3rem;   --esp-3xl: 4rem;  --esp-4xl: 6rem;
}

Repare no exemplo do dia 29/09: o cabeçalho do Bikcraft começa com padding: 16px no celular e só ganha 100px nas laterais a partir de 1024px. Isso é exatamente o padrão da tabela.

5.3 Área de toque (touch target)

O dedo é bem menos preciso que o mouse. Os guias de acessibilidade e das plataformas pedem:

  • Mínimo 44 × 44px (Apple Human Interface Guidelines / WCAG 2.5.5 nível AAA)
  • 48 × 48px (Material Design / Android)
  • Pelo menos 8px de distância entre dois alvos de toque
nav a { display: inline-block; padding: 12px 16px; min-height: 44px; }

6. Larguras de conteúdo (container)

Em telas grandes, o conteúdo não deve ocupar 100% da largura. Padrão de mercado: um container centralizado com largura máxima.

Tipo de conteúdomax-width comum
Texto corrido (artigo, blog)65ch ou 680–720px
Site institucional / e-commerce1140 – 1200px
Dashboards / sistemas1400px ou 100%
.container {
  width: 100%;
  max-width: 1200px;
  margin-inline: auto;     /* centraliza */
  padding-inline: 16px;    /* respiro no celular */
}

8. Imagens e mídia

  • Imagem fluida: img { max-width:100%; height:auto; }. É a primeira regra de qualquer CSS responsivo.
  • Proporções comuns: 16:9 (vídeo/banner), 4:3 (foto), 1:1 (avatar/produto). Use aspect-ratio: 16 / 9; para reservar o espaço e evitar "pulos" no carregamento.
  • Largura de imagem de banner (hero): 1600 a 1920px de largura é suficiente para desktop; em celular carregue versão menor (srcset).
  • Formatos: WebP/AVIF para fotos, SVG para ícones e ilustrações (como as bike-*.svg do exercício).

9. Como o navegador decide a largura: o meta viewport

Sem esta linha no <head>, o celular finge ter uma tela de 980px e encolhe a página inteira para caber. Nenhuma media query funciona de verdade:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

10. Como conferir tudo isso na prática

  1. Abra a página no Chrome e pressione F12.
  2. Clique no ícone de dispositivo (ou Ctrl + Shift + M) para ativar o modo responsivo.
  3. No topo, escolha um aparelho da lista (iPhone SE, iPad Air…) ou Responsive e digite a largura manualmente.
  4. Arraste a borda direita devagar: observe onde o layout "quebra".
  5. Use o menu de três pontinhos → Show media queries para ver as barras coloridas dos breakpoints acima da tela.
