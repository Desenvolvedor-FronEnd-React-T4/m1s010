A · Classes

O que é uma classe

<!-- HTML: etiqueta no elemento (sem ponto) -->
<button class="botao">Enviar</button>

/* CSS: a regra procura a etiqueta (com ponto) */
.botao { background:#1b4f72; color:#fff; padding:10px 20px; }
  • Pode ter várias classes no mesmo elemento: class="botao botao--grande"
  • Nome por função, não aparência: botao-primario, não botao-azul
  • Minúsculas com hífen: card-produto

Estilize com classe. Reserve o id para âncora e JavaScript.

A · Classes

container: o padrão "faixa + container"

.container {
  max-width: 1100px;  /* teto, nunca estoura o celular */
  margin: 0 auto;     /* centraliza */
  padding: 0 16px;
}
<section class="secao">        <!-- faixa: fundo 100% -->
  <div class="container">      <!-- conteúdo: largura limitada -->
    ...
  </div>
</section>

Por que max-width e não width? Largura fixa estoura o celular.

A · Classes

Layout: flex ou grid?

Flexbox: uma dimensão

Menu, barra de botões, centralizar, linha de cards.

.flex { display:flex; gap:16px; }

Grid: duas dimensões

Galeria, catálogo, layout de página.

.grid { display:grid; gap:16px;
 grid-template-columns:
  repeat(auto-fit,minmax(240px,1fr)); }

A classe de layout vai no pai. Quem se organiza são os filhos diretos.

B · Herança

O que é herança

body font-family e color declarados aqui, uma vez
main
section
p herda fonte e cor sem ninguém pedir
  • O filho recebe do pai certos valores, automaticamente.
  • Declaração direta no filho sempre vence a herdada.
B · Herança

O que herda e o que não herda

✅ Herdam (texto)

  • color
  • font-*
  • line-height
  • text-align
  • cursor, visibility

❌ Não herdam (caixa)

  • margin, padding
  • border
  • background
  • width, height
  • display, position

Se toda div herdasse a borda do pai, a página viraria uma cebola de molduras.

B · Herança

Receita profissional da base

body { font-family: Arial, sans-serif;
       line-height: 1.6; color: #263238; }
a { color: inherit; }                          /* link não herda sozinho */
input, button, textarea, select { font: inherit; }
ValorFaz
inheritForça herdar do pai
initialVolta ao padrão do CSS
unsetinherit se herda, initial se não
B · Cascata

Efeito cascata: as 3 perguntas, nesta ordem

1Origem e importância — navegador < autor? Tem !important?
2Especificidade — qual seletor é mais forte?
3Ordem no código — empatou? A última vence.
p      { color: blue; font-size: 18px; }
.aviso { color: green; }
/* <p class="aviso"> → verde (da classe) e 18px (do p).
   Regras se somam; só brigam onde discordam. */

O placar tem 4 colunas

Compara da esquerda para a direita. A primeira coluna maior ganha; as outras nem são olhadas.

p0-0-0-1.card h20-0-1-1
.card0-0-1-0#lojas .card h20-1-1-1
C · Especificidade

Uma classe vence 7 tags empilhadas

.botao { color: red; }                             /* 0-0-1-0 */
html body main section div p a { color: blue; }    /* 0-0-0-7 */
/* vermelho: 1 na coluna C ganha de 7 na coluna D */

Um id vence 100 classes

#topo (0-1-0-0) > .a.b.c… (0-0-N-0)

Herança não entra no placar

Valor herdado perde para qualquer regra direta.

Empate nas 4 colunas? Vence a última escrita no CSS.

C · Conflitos

O link que não muda de cor

.menu a   { color: white; }   /* 0-0-1-1 */
.destaque { color: gold; }    /* 0-0-1-0 → perde! */
.menu .destaque { color: gold; }   /* 0-0-2-0 → vence, sem !important */

Armas, da mais saudável à pior

1 Reordenar · 2 Classe simples · 3 Mais uma classe no seletor · 4 :where() · 5 !important · 6 id / inline

C · Predominância semântica

Hierarquia de poder, de propósito

Tags (base) 0-0-0-1 · o piso do site
Classes de componente 0-0-1-0 · a regra de cada peça
Modificadores e estados vêm depois do componente e vencem
Utilitárias por último · a palavra final do dev

Mantra: baixa especificidade + ordem organizada = nunca lutar com a cascata.

C · Atividade

Quiz rápido: quem vence?

.titulo { color: red; }
.titulo { color: green; }

→ ?

#topo { color: red; }
.a.b.c.d.e.f { color: blue; }

→ ?

.menu a { color: white; }
.destaque { color: gold; }

→ ?

.btn { background:blue !important; }
<button style="background:red">

→ ?

Respostas: verde (última) · vermelho (id) · branco (0-0-1-1 > 0-0-1-0) · azul (!important)

D · O mapa

Esqueleto de uma página profissional

<html lang="pt-BR"> ① documento
<head> ② invisível: charset · viewport · title · link do CSS
<body> ③ o que o usuário vê · fonte base (herança)
<header> ④ topo do site
<main> ⑤ conteúdo único · só 1
<footer> ⑧ base
section → div.container → h1 · p · .card ⑥ ⑦ dentro do main

Camadas 1–3: tags semânticas. Camada 4: reino da div. Camada 5: mistura.

D · Decisão

Div, main, section ou article?

<main>

Conteúdo principal e único da página. Só um.

<section>

Grupo sobre um tema, com título (h2).

<article>

Peça independente: produto, post, card.

<aside>

Apoio, dispensável: lateral, "leia também".

<nav>

Grupo principal de links.

<div>

Último recurso. Só agrupa para o CSS.

Existe tag com o significado? Use. Senão, div.

D · Decisão

Os pares que confundem

section ou div?

Tirando o CSS, a caixa ainda faz sentido no documento? Sim → section. Não → div.

section ou article?

Posso copiar para outro site e continua fazendo sentido? Sim → article.

link ou botão?

Muda de página → a. Executa ação → button.

Erros clássicos

Dois main · "divite" · div com onclick · section só para pintar fundo.

D · Qual classe começa?

A ordem de escrita do CSS

1Reset
2Variáveis (:root)
3Base (tags + herança)
4Estrutura (.container)
5Layout (.grid, .flex)
6Componentes
7Modificadores e estados
8Utilitárias e media queries

Do geral ao específico: em empate, o que vem depois vence. A ordem no atributo class="" do HTML não importa.

D · Avançado

Nomenclatura BEM e organização

.card              /* Bloco */

projeto/
├── index.html
├── estilo.css
├── script.js

  • Todo seletor é uma classe só (0-0-1-0): sem briga de peso.
  • Prefixo = dono: hero-titulo, card-loja, coluna-dados.
  • Um idioma só, sem numeração (caixa2).
