Regra de ouro do guia: HTML diz o que a coisa é. CSS diz como ela parece. A classe é a ponte entre os dois.

O que é uma classe CSS

Uma classe é uma etiqueta que você cola num elemento HTML para que o CSS consiga encontrá-lo e estilizá-lo. A classe não faz nada sozinha: ela só ganha poder quando existe uma regra CSS com o mesmo nome.

As três partes

<!-- HTML: o elemento recebe a etiqueta -->
<button class="botao">Enviar</button>

/* CSS: a regra procura a etiqueta (o ponto significa "classe") */
.botao {
  background: #1b4f72;
  color: #fff;
  padding: 10px 20px;
}
  • Nome: botao. Você escolhe. O navegador não liga para o significado.
  • Ponto (.): só aparece no CSS. No HTML escreve-se class="botao", sem ponto.
  • Declarações: o que está entre chaves, no formato propriedade: valor;.

Papel de uma classe

Toda classe responde a uma de quatro perguntas. Saber qual é a pergunta é o que separa um nome bom de um nome ruim.

PapelPergunta que respondeExemplos
EstruturaOnde esse bloco fica e qual a largura dele?container, wrapper, secao
LayoutComo os filhos se organizam?flex, grid, row, col
ComponenteQue peça reutilizável é essa?botao, card, navbar
UtilitáriaQual ajuste pequeno e único aplico?mt-2, text-center, hidden
Estado/modificadorEm que situação ou variação está?ativo, is-open, botao--grande

Cada um desses papéis tem um documento próprio (03 a 08).

Regras de sintaxe do nome

  • Pode ter letras, números, hífen (-) e sublinhado (_).
  • Não pode começar com número (1coluna não funciona; coluna-1 funciona).
  • Diferencia maiúscula de minúscula: .Botao e .botao são classes diferentes.
  • Sem espaço. Espaço no atributo class separa várias classes.

Várias classes no mesmo elemento

<button class="botao botao--grande ativo">Comprar</button>

São três etiquetas no mesmo botão. As regras das três valem juntas. Esse é o mecanismo que permite combinar componente, variação e estado.

Classes de estrutura

São as classes que definem largura, centralização e ritmo vertical da página. Quase todo site profissional começa por elas. A mais famosa é a container.

container

Função: limitar a largura do conteúdo e centralizá-lo. Sem ele, em monitor grande o texto estica de ponta a ponta e fica ilegível.

.container {
  width: 100%;
  max-width: 1100px;   /* nunca passa disso */
  margin: 0 auto;      /* auto dos lados = centraliza */
  padding: 0 16px;     /* respiro nas bordas do celular */
}

Como se comporta

conteúdo centralizado, no máximo 420px (exemplo)

Detalhe importante: o fundo pode ocupar a tela inteira (na section) enquanto o conteúdo fica no container dentro dela. Veja o padrão abaixo.

O padrão "faixa + container"

<section class="secao secao-escura">      <!-- faixa de fundo: 100% da largura -->
  <div class="container">                 <!-- conteúdo: largura limitada -->
    <h2>Nossas bikes</h2>
    ...
  </div>
</section>

É o padrão mais comum do mercado. A faixa pinta a tela toda; o container alinha o conteúdo.

Container x wrapper: qual a diferença?

Na prática os dois fazem parte da mesma família, e equipes diferentes usam nomes diferentes. A convenção mais útil para a sala:

  • container = controla largura horizontal do conteúdo.
  • wrapper = embrulha um grupo para dar-lhe comportamento próprio (altura mínima, posição relativa, overflow).

O importante é escolher uma convenção e repetir no projeto inteiro.

Pergunta de revisão: por que o container usa max-width e não width? Resposta: width fixa estoura o celular; max-width encolhe junto com a tela e só limita o teto.

Classes de layout

Classes de layout dizem como os filhos de um elemento se organizam: em linha, em coluna, em grade. A regra mental: a classe vai no pai, e quem se organiza são os filhos.

Flexbox: organizar em uma direção

.flex { display: flex; }
.flex-coluna { flex-direction: column; }
.centralizado { justify-content: center; align-items: center; }
.espaco-entre { justify-content: space-between; }
.quebra { flex-wrap: wrap; }
.gap { gap: 16px; }

Regra prática: uma dimensão (linha ou coluna) → flex. Duas dimensões (linhas e colunas) → grid.

row e col (Bootstrap) e colunas do projeto

Em frameworks, o layout vira vocabulário pronto:

<div class="container">
  <div class="row">
    <div class="col-md-6">Dados</div>
    <div class="col-md-6">Formulário</div>
  </div>
</div>
  • row: a linha (por baixo é display: flex; flex-wrap: wrap).
  • col-md-6: "a partir da tela média, ocupe 6 de 12 partes (metade)".

Em CSS puro você cria o mesmo com nome por função, como a coluna-dados e a coluna-formulario da página de contato da Bikcraft.

Classes de componentes

Um componente é uma peça reutilizável da interface, com visual completo: botão, card, menu, formulário. A classe de componente entrega a peça inteira. É a classe mais comum em projetos reais.

Anatomia de um componente

Um componente tem um bloco (a peça) e partes (o que existe dentro dela). Os nomes das partes começam pelo nome do bloco.

botao

.botao {
  display: inline-block;
  padding: 10px 20px;
  border-radius: 6px;
  background: #1b4f72; color: #fff;
  text-decoration: none; font-weight: bold;
}
.botao:hover { background: #123049; }

Resultado

Enviar mensagem

Serve para <button> e para <a> que parece botão. Escolha a tag pelo comportamento (ação → button; navegação → a) e a classe pelo visual.

card

<article class="card">
  <img class="card-imagem" src="bike.svg" alt="Bike urbana">
  <h3 class="card-titulo">Urbana</h3>
  <p class="card-texto">Leve e prática.</p>
  <a class="botao" href="#">Ver</a>
</article>

Resultado

Urbana

Leve e prática.

Ver

Note os nomes: card-imagem, card-titulo, card-texto. Quem lê o HTML entende o dono de cada pedaço.

badge

Resultado

Classes de texto e tipografia

Tipografia é o que mais pesa na aparência de um site. As classes de texto controlam tamanho, peso, alinhamento e cor. Há uma regra que vale para todas: a tag diz o nível do texto; a classe diz o visual.

Tag para significado, classe para aparência

Errado: <p class="titulo-grande"> só para parecer título. Leitor de tela e Google não reconhecem como título.

Certo: <h2 class="titulo-secao">. A tag dá o nível correto; a classe ajusta o tamanho.

Também vale o contrário: se um <h3> precisa parecer pequeno, mantenha o h3 e reduza com classe. Nunca troque o nível só pelo tamanho.

Propriedades de texto que precisam estar no seu vocabulário

  • font-family: a fonte (sempre com alternativas: "Inter", Arial, sans-serif).
  • font-size: use rem para respeitar a configuração do usuário.
  • font-weight: 400 normal, 700 negrito.
  • line-height: altura da linha; 1.5 a 1.7 é ótimo para parágrafos.
  • text-align, letter-spacing, text-decoration.

Onde declarar a fonte? Uma vez só, no body. Todo o resto herda (documento 10). Quem repete font-family em dez classes está lutando contra o CSS.

Hierarquia de título: a "escada"

<h1>  um por página (o assunto da página)
  <h2>  cada seção
    <h3>  subtítulos dentro da seção
      <h4>  detalhes (raro)

Não pule degraus (de h1 direto para h4) e use um único h1 por página.

Classes utilitárias

Uma classe utilitária faz uma única coisa, sempre a mesma, em qualquer lugar. É o contrário do componente: não entrega uma peça pronta, entrega um ajuste fino.

Exemplos clássicos

.mt-2  { margin-top: 8px; }
.mb-4  { margin-bottom: 24px; }
.p-3   { padding: 16px; }
.text-center { text-align: center; }
.hidden { display: none; }
.w-100 { width: 100%; }
.sr-only { /* escondido da tela, mas lido por leitor de tela */
  position: absolute; width: 1px; height: 1px;
  overflow: hidden; clip: rect(0 0 0 0); white-space: nowrap;
}

Por que existem

Sem utilitárias, cada ajuste de 8px viraria uma classe nova. Com elas, você resolve um detalhe sem inventar nome:

<section class="secao text-center mb-4">...</section>

Escala de espaçamento

Profissionais não usam números aleatórios; usam uma escala. Assim a página inteira respira no mesmo ritmo.

Leitura do nome: mt = margin-top, mb = bottom, ms/me = start/end, mx = eixo horizontal, my = vertical; p… = padding.

Cuidado: utilitárias costumam ser escritas depois de tudo no CSS (documento 20) para vencer o componente em caso de empate. É assim que mt-0 consegue anular a margem de um card.

Tailwind CSS leva essa ideia ao limite: todo o visual vem de utilitárias (flex p-4 text-center). É a abordagem "utility-first" citada na atividade da biblioteca.

Classes de estado e modificadores

Duas ideias parecidas, mas diferentes. Modificador = uma variação fixa do componente (grande, perigo). Estado = uma situação que muda com o uso (aberto, ativo, desabilitado).

Modificador: a variação do componente

O componente base fica sozinho e os modificadores só alteram o que for diferente.

.botao { padding: 8px 16px; background: #cfd8dc; }
.botao--primario { background: #1b4f72; color: #fff; }
.botao--perigo   { background: #c0392b; color: #fff; }
.botao--grande   { padding: 14px 28px; }
<button class="botao">Cancelar</button>
<button class="botao botao--primario">Salvar</button>
<button class="botao botao--perigo botao--grande">Excluir</button>

Resultado

O duplo hífen (--) é a convenção BEM (documento 21) para "modificador". Quem lê sabe que botao--grande depende de botao.

Estado: a situação do momento

O estado muda por causa de uma ação do usuário, normalmente com JavaScript ligando e desligando a classe.

.menu { display: none; }
.menu.is-open { display: block; }   /* JS adiciona e remove is-open */

.botao.ativo { outline: 3px solid gold; }

Botão "ativo"

Pseudoclasses: os estados nativos do CSS

Alguns estados o navegador já conhece. Não precisa de classe nem JavaScript.

Não remova o :focus (outline: none) sem colocar outro indicador no lugar. Quem navega por teclado fica perdido.

O que é herança

Herança é quando um elemento filho recebe automaticamente certos valores do elemento pai, sem que você escreva nada para ele. É o motivo de bastar declarar a fonte uma vez no body.

A árvore do HTML

Todo HTML é uma árvore de elementos aninhados. Quem está dentro é filho; quem envolve é pai; quem está acima de todos é ancestral.

body font-family e color definidos aqui
main
section
p herda a fonte e a cor de body, sem ninguém pedir

Exemplo mínimo

body { font-family: Arial, sans-serif; color: #263238; }

/* Não existe regra de fonte para h1, p, li, a... e mesmo assim todos usam Arial */

Pai com cor e fonte; filhos sem regra nenhuma

Eu sou o pai (Georgia, azul).

Eu sou um p filho, sem CSS próprio: herdei a fonte e a cor.

  • Item de lista, também herdou.

Por que a herança existe

  • Economia: uma declaração no ancestral vale para centenas de filhos.
  • Consistência: a página inteira fala a mesma "língua" visual.
  • Manutenção: mudar a fonte do site é mexer em uma linha.

Herança x cascata: não confunda

HerançaCascata
Pergunta"De quem este elemento recebe o valor?""Quando duas regras dizem coisas diferentes, qual vale?"
DireçãoDo pai para o filhoEntre regras que atingem o mesmo elemento
Documento10 e 1112, 13 e 14

Analogia: herança é o sobrenome da família: você recebe sem pedir. Se você disser "meu nome é outro", o que você mesmo declarou vence o que herdou. Uma regra direta no filho sempre ganha da herança.

body { color: #263238; }
.aviso { color: #c0392b; }   /* o .aviso não herda mais a cor: usa a própria */

Atenção: nem tudo é herdado. Borda, margem e fundo, por exemplo, não passam do pai para o filho. É o assunto do próximo documento.

O que herda e o que não herda

A regra geral: propriedades de texto são herdadas; propriedades de caixa (tamanho, borda, fundo, espaço) não são. Faz sentido: se toda div herdasse a borda do pai, a página viraria uma cebola de molduras.

Tabela de referência

✅ Herdam

  • color
  • font-family, font-size, font-weight, font-style
  • line-height
  • text-align, letter-spacing
  • visibility
  • cursor
  • list-style

❌ Não herdam

  • margin, padding
  • border
  • background
  • width, height
  • display, position
  • overflow
  • box-shadow, opacity

Pai com borda + cor verde. Quem herdou o quê?

Pai: tem borda e texto verde.

Filho p: o texto ficou verde (herdou), mas sem borda (não herda).

Casos que pegam todo mundo

1. Links não herdam a cor do pai

O navegador dá ao <a> uma cor própria (azul). Para o link acompanhar o texto ao redor:

a { color: inherit; text-decoration: none; }

2. Campos de formulário não herdam a fonte

input, button, select e textarea usam a fonte do sistema. Reset profissional:

input, button, select, textarea { font: inherit; }

3. line-height herda como número, não como valor calculado

line-height: 1.5 (sem unidade) é recalculado em cada filho conforme o tamanho da fonte dele. line-height: 24px passa fixo. Prefira o número sem unidade.

Palavras-chave que controlam a herança

ValorO que fazExemplo
inheritForça herdar do pai, mesmo em propriedade que normalmente não herdaborder: inherit;, color: inherit;
initialVolta ao valor padrão da especificação CSSdisplay: initial;
unsetSe a propriedade herda → inherit; se não → initialall: unset;
revertVolta ao estilo padrão do navegadorcolor: revert;

Receita profissional para a base do site:

body { font-family: Arial, sans-serif; line-height: 1.6; color: #263238; }
a { color: inherit; }
input, button, textarea, select { font: inherit; }

Três linhas de herança bem usada evitam dezenas de classes repetidas.

O efeito cascata

CSS significa Cascading Style Sheets: folhas de estilo em cascata. Cascata é o algoritmo que decide qual regra vence quando várias regras atingem o mesmo elemento e dizem coisas diferentes sobre a mesma propriedade.

O problema que a cascata resolve

p { color: blue; }
p { color: red; }
.aviso { color: green; }

<p class="aviso">De que cor eu fico?</p>

Três regras, três cores, um parágrafo. O navegador não pode obedecer às três. A cascata é o desempate. (Resposta: verde, e você vai saber por quê já já.)

As três perguntas, nesta ordem

O navegador pergunta, na sequência, e para assim que alguém vence:

  1. Origem e importância. De onde vem a regra: estilo do navegador, do autor (você) ou do usuário? Tem !important?
  2. Especificidade. Qual seletor é mais específico? (Detalhado no documento 14.)
  3. Ordem no código. Se empatou nas duas, a última escrita vence.
1. Há !important ou origens diferentes?
↓ não, empatou
2. Um seletor é mais específico?
↓ não, empatou
3. Qual aparece por último no CSS?
↓
Essa vence

1. Origem

OrigemQuem escrevePeso
Navegador (user agent)Chrome, Firefox… (azul do link, margem do body)Menor
AutorVocê, no seu arquivo .cssMaior que a do navegador
UsuárioPreferências de acessibilidadeEntre as duas

Por isso o seu CSS sempre vence o estilo padrão do navegador, mesmo com seletores simples.

3. Ordem: a última vence (em caso de empate)

.ex-ordem { color: #1b4f72; }   /* azul */
.ex-ordem { color: #c0392b; }   /* vermelho — vem depois, vence */

Duas regras com a mesma especificidade: vermelho (a última)

Este texto aparece vermelho.

Ordem também vale entre arquivos

<link rel="stylesheet" href="base.css">
<link rel="stylesheet" href="pagina.css">   <!-- vem depois: ganha os empates -->

Por isso o reset e a base vêm primeiro, e o CSS da página, depois.

Por que "cascata"?

Como uma cachoeira, o estilo desce de cima (navegador) para baixo (seu CSS, regra por regra), e o que chega por último ao elemento é o que ele mostra. Cada regra "sobrescreve" a anterior apenas nas propriedades em que discordam; as outras continuam valendo.

p      { color: blue; font-size: 18px; }
.aviso { color: green; }
/* Resultado em <p class="aviso">: cor verde (do .aviso), tamanho 18px (do p).
   As regras se SOMAM nas propriedades diferentes e só brigam nas iguais. */

Resumo em uma frase: a cascata combina todas as regras que atingem o elemento; onde elas discordam, vence a de maior importância → maior especificidade → mais tarde no código.

Cascata na prática com o DevTools

Teoria entra de verdade quando você vê a cascata. O DevTools mostra, para cada elemento, todas as regras que o atingem, quais venceram e quais foram riscadas.

Passo a passo no navegador

  1. Abra a página e aperte F12 (ou clique com o botão direito → Inspecionar).
  2. Clique na seta do canto da janela e depois no elemento que quer investigar.
  3. Na aba Elementos, olhe o painel Estilos (Styles).
  4. Leia de cima para baixo: regras mais fortes ficam em cima.
  5. Propriedade riscada = perdeu a briga. Passe o mouse e o navegador mostra por quê.
  6. Mais abaixo, "Inherited from …" mostra o que veio por herança.
  7. Aba Computed (Computado): o valor final de cada propriedade.

Laboratório 1: descubra o vencedor

.t1 { color: #c0392b; }
p   { color: #1e8449; }

<p class="t1">Qual cor?</p>

Inspecione este parágrafo com F12

Qual cor? (vermelha: classe vence tag)

No DevTools você verá p { color: green } riscada.

Laboratório 2: regras se somam

.t2         { color: #1b4f72; font-size: 1.2rem; }
.t2.negrito { font-weight: bold; }

Duas regras, zero conflito: ambas valem

Azul, grande e negrito.

Nenhuma foi riscada, porque nenhuma discorda da outra.

!important: o botão vermelho

p { color: red !important; }

!important pula as etapas 2 e 3 da cascata. Nada que o autor escrever sem ele consegue vencer.

Por que evitar: a única forma de vencer um !important é outro !important mais forte. A manutenção vira uma corrida armamentista. Se você precisou dele, quase sempre o problema é de especificidade (documento 15).

Usos legítimos: utilitárias que precisam sempre vencer (.hidden { display: none !important; }) e sobrescrever CSS de terceiros que você não controla.

O atributo style no HTML

<p style="color: red">

Estilo inline vence qualquer seletor de arquivo, sem precisar de !important. Por isso se evita no dia a dia: ele escapa da organização do CSS e só pode ser vencido por !important.

Checklist de investigação

  • ☐ O seletor realmente encontra o elemento? (erro de digitação, ponto esquecido)
  • ☐ O arquivo CSS foi carregado? (aba Network / link quebrado)
  • ☐ Outra regra mais específica sobrescreve a minha?
  • ☐ Duas regras empatam e a última do arquivo vence?
  • ☐ A propriedade herda? Se não, preciso declará-la no próprio elemento.

O placar de especificidade

Especificidade é a nota que o navegador dá a cada seletor. Entre duas regras que brigam, a de maior nota vence, independentemente da ordem no arquivo. É assim que se decide a predominância entre classes, ids e tags.

O placar tem 4 colunas

Pense num placar A – B – C – D. Compara-se coluna por coluna, da esquerda para a direita. A primeira coluna que tiver número maior ganha, e as demais nem são olhadas.

Como comparar: o exemplo mais importante da trilha

Uma classe vence onze tags empilhadas, porque a coluna C pesa mais do que qualquer quantidade na coluna D:

.botao        { color: red; }      /* 0-0-1-0 */
html body main section div p a { color: blue; }  /* 0-0-0-7 */
/* Vence .botao: 1 na coluna C ganha de 7 na coluna D */

A mesma lógica vale um nível acima: um id vence cem classes.

Mesmo elemento, class + id. A ordem no CSS é .x1 depois #x1; quem aparece azul?

Azul: o id (0-1-0-0) vence a classe (0-0-1-0), mesmo se a classe viesse por último.

O que NÃO conta pontos

  • O seletor universal *.
  • Combinadores: espaço, >, +, ~.
  • :where( ) → sempre zero. :is( ) e :not( ) → valem o item mais forte lá dentro.

Empate: volta a regra da ordem

Se o placar é igual nas quatro colunas, vence a regra que vem por último no código (documento 12).

Pegadinha de herança: um valor herdado perde para qualquer regra direta no elemento, mesmo a de especificidade 0-0-0-1. Herança não entra no placar: ela só preenche o que ninguém declarou.

Conflitos reais e como resolvê-los

Esta é a parte prática: "o meu CSS não funciona". Quase sempre a causa é um desses cinco casos. Cada um tem a solução profissional, que raramente é usar !important.

Caso 1: o link que não muda de cor

.menu a  { color: #fff; }        /* 0-0-1-1 */
.destaque { color: gold; }       /* 0-0-1-0 — perde! */

<nav class="menu"><a class="destaque" href="#">Contato</a></nav>

Diagnóstico: .menu a pesa 0-0-1-1; .destaque pesa 0-0-1-0. A mais pesada vence, mesmo vindo antes.

Solução profissional: igualar ou superar o peso com seletor, não com força bruta.

.menu .destaque { color: gold; }   /* 0-0-2-0 — vence */

Caso 2: o seletor muito longo

body main section.hero div.container h1.titulo { ... }   /* 0-0-3-4 */

Quem for sobrescrever precisará de um seletor ainda maior. Cada seletor longo "contamina" o projeto.

Solução: uma classe, só uma, direto no elemento.

.hero-titulo { ... }   /* 0-0-1-0 */

Caso 3: o id no CSS

#topo { background: navy; }      /* 0-1-0-0: nenhuma classe consegue vencer */

Solução: troque por classe. Mantenha o id para âncora e JavaScript.

Caso 4: a ordem dos arquivos

Seu componente não pega porque o CSS do framework está depois do seu.

<link rel="stylesheet" href="meu.css">
<link rel="stylesheet" href="bootstrap.css">   <!-- vem depois: ganha os empates -->

Solução: framework primeiro, o seu depois.

Caso 5: modificador que não "pega"

.botao--perigo { background: red; }   /* escrito ANTES de .botao */
.botao         { background: gray; }  /* mesmo peso, vem depois: vence */

Solução: base primeiro, modificadores e estados depois. Documento 20.

Resumo das armas, da mais saudável à pior

#FerramentaAvaliação
1Reordenar o CSS✅ Grátis, não cria dívida
2Trocar para uma classe simples✅ Melhor correção de raiz
3Acrescentar uma classe ao seletor (.menu .destaque)🟡 Aceitável, cuidado com a escalada
4:where() para zerar o peso de base🟡 Avançado e elegante

Predominância semântica: o princípio por trás de tudo

Para a pergunta "que classe predomina?", a resposta de projeto é uma hierarquia de poder deliberada:

Tags (base)0-0-0-1: o piso. Define o padrão do site.
Classes de componente0-0-1-0: a regra geral de cada peça.
Modificadores e estadosvêm depois e vencem o componente.
Utilitáriaspor último: precisam vencer tudo (às vezes com !important).

Quanto mais "específico em significado" o ajuste, mais tarde ele entra no CSS. Assim, a vontade do desenvolvedor ("este botão é perigoso", "esta margem é zero") sempre prevalece sobre o padrão genérico, sem recorrer a briga de peso.

Mantra: baixa especificidade, ordem organizada. Se você escreve seletores de peso 0-0-1-0 na ordem certa, nunca precisará lutar com a cascata.

Parte 4 — Desafio de equipe

O CSS abaixo tem 3 problemas de predominância. Encontre e corrija sem usar !important.

#cabecalho .menu ul li a { color: white; }
.botao { background: gray; }
.botao--primario { background: blue; }   /* vem antes de .botao no arquivo real */
body main section div.container p { font-size: 14px; }
.texto-grande { font-size: 24px; }
Ver gabarito
  1. Seletor longo com id (0-1-1-3): troque por .menu-link { color: white; }.
  2. Ordem: .botao--primario deve ser escrito depois de .botao.
  3. Seletor longo (0-0-1-5) impede .texto-grande de vencer: troque por .paragrafo { font-size: 14px; } e coloque .texto-grande depois.

Pares que confundem

section ou div?

section: o grupo tem um tema e um título. Se você consegue nomear no sumário da página, é section.

div: só existe para o CSS (largura, grade, fundo).

Teste: "Se eu tirar o CSS, essa caixa ainda faz sentido como parte do documento?" Sim → section. Não → div.

section ou article?

article: peça independente e reaproveitável (card de produto, post, comentário).

section: pedaço de algo maior.

Teste: "Posso copiar para outro site e continua fazendo sentido?" Sim → article.

header ou section.hero?

header do site: topo com logo e menu. O hero é a primeira section do main.

Um header também pode abrir um article (título + data do post).

aside ou div.lateral?

aside: o conteúdo é complementar (links relacionados, anúncios, biografia).

div: uma coluna de layout que faz parte do texto principal.

Qual classe começa? A ordem de escrita do CSS

A pergunta clássica: "por onde eu começo o CSS?". A resposta profissional é uma ordem em camadas, do mais geral ao mais específico. É a mesma lógica da cascata: o que vem depois vence os empates, então o mais genérico vem antes.

A escada das 8 camadas

  1. Reset / normalização. Zera diferenças entre navegadores: * { box-sizing: border-box; }, margens do body.
  2. Variáveis (tokens). Cores, fontes, espaços em um só lugar: :root { --azul: #1b4f72; }
  3. Base (tags). body, h1…h6, p, a, img. Aqui entra a herança: fonte, cor, line-height.
  4. Estrutura. .container, .secao. O esqueleto de largura e respiro.
  5. Layout. .grid, .flex, colunas. Como os blocos se organizam.
  6. Componentes. .botao, .card, .menu, .rodape, na ordem em que aparecem na página.
  7. Modificadores e estados. .botao--primario, .is-open. Depois do componente que alteram.
  8. Utilitárias e media queries. .text-center, .hidden e, por último, as media queries que ajustam tudo para telas maiores.

Por que nesta ordem?

CamadaMotivo de vir nessa posição
Reset e base primeiroSão o piso. Qualquer classe precisa vencê-los sem esforço.
Estrutura antes dos componentesQuase todo componente vive dentro de um container.
Modificador depois do componenteMesmo peso 0-0-1-0, vence quem vem por último.
Utilitárias no fimSão a "palavra final" do desenvolvedor.
Media queries no fimMesmo peso que a regra base; precisam vir depois para sobrescrevê-la.

Mobile-first: a base é o celular

As regras fora de media query descrevem o celular. Telas maiores entram por min-width:

.grid { grid-template-columns: 1fr; }              /* celular */
@media (min-width: 768px) {
  .grid { grid-template-columns: repeat(3, 1fr); } /* tablet para cima */
}

E no HTML, qual classe aparece primeiro?

Escreva as classes em ordem de geral → específico. A ordem no atributo class não muda a cascata (quem manda é a ordem no CSS), mas é uma convenção que facilita a leitura:

<button class="botao botao--primario botao--grande mt-3">
         componente  variação      variação   utilitária

Pegadinha: a ordem das classes dentro do class="..." do HTML não importa para quem vence. Quem decide é a posição da regra no arquivo CSS, depois da especificidade.

Nomenclatura (BEM) e organização de arquivos

Nomes ruins causam conflitos; nomes bons se explicam sozinhos. BEM é a convenção mais usada do mercado para nomear classes. Junto com uma estrutura de pastas simples, é o que faz um projeto crescer sem virar bagunça.

BEM: Bloco, Elemento, Modificador

ParteSintaxeExemploSignifica
BlocoblococardA peça independente
Elementobloco__elementocard__tituloUma parte que só existe dentro do bloco
Modificadorbloco--variacaocard--destaqueUma variação ou estado
 
<article class="card card--destaque">
  <img class="card__imagem" src="bike.svg" alt="Bike">
  <h3 class="card__titulo">Urbana</h3>
  <a class="card__link botao" href="#">Ver</a>
</article>
.card { ... }
.card__imagem { ... }
.card__titulo { ... }
.card--destaque { border-color: gold; }

Por que BEM resolve problema de predominância

  • Todo seletor é uma classe só (0-0-1-0): nunca há briga de peso.
  • Sem seletores aninhados como .card h3, mexer em um componente não quebra outro.
  • O nome informa a hierarquia: card__titulo pertence ao card.

Não aninhe os nomes: escreva card__titulo, não card__corpo__titulo. Elemento é sempre filho do bloco, mesmo que esteja no meio de outras divs.

Seu projeto, sem BEM rígido

Na sala usamos a versão leve: hero, hero-titulo, card-loja, coluna-dados. A ideia é a mesma: prefixo = dono. Importante é ser consistente.

Regras gerais de nomeação

  1. Minúsculas e hífens (kebab-case), nunca espaço ou acento.
  2. Nome por função, não por aparência: botao-primario, não botao-azul.
  3. Português ou inglês, mas um só em todo o projeto.
  4. Nada de numeração (caixa2, div3): o nome deve dizer o conteúdo.
  5. Prefixo para estado: is- / has- (controlados por JS).
  6. Prefixo para JS: js- quando a classe existe só para script, nunca para estilo.

Do básico ao avançado e checklist profissional

Para fechar: a escada de evolução (onde você está, qual o próximo degrau) e um checklist para revisar qualquer página antes de entregar.

A escada em 5 níveis

Nível 1 — Raiz: a página funciona

Sabe: html/head/body, títulos, parágrafos, links, imagens, listas. Cria classes e aplica cor e fonte.

Típico: usa só div e span. Estiliza por tag.

Próximo degrau: trocar div por tags semânticas (docs 17–19).

Nível 2 — Estrutura: a página tem esqueleto

Sabe: header / main / section / footer, container, uma classe por função, hierarquia h1→h2→h3.

Próximo degrau: dominar layout (flex, grid) e herança (docs 04, 10, 11).

Nível 3 — Layout: a página se adapta

Sabe: flexbox e grid, rem/%/vw, mobile-first com min-width, imagens fluidas.

Próximo degrau: entender a cascata a fundo e sair do "tentativa e erro" (docs 12–15).

Nível 4 — Cascata: o CSS é previsível

Sabe: calcula especificidade de cabeça, não usa id nem !important para estilizar, ordena o CSS em camadas, depura com DevTools.

Próximo degrau: nomenclatura e arquitetura (doc 21).

Nível 5 — Arquitetura: o projeto escala

Sabe: BEM, variáveis CSS (tokens), componentes reutilizáveis, arquivos organizados, acessibilidade (rótulos, foco, contraste, alt), escolhe biblioteca (Bootstrap/Tailwind) por critério.

Depois disso: @layer, :where(), clamp(), container queries, CSS com JavaScript e frameworks (React).

Checklist de revisão profissional

HTML

  • ☐ Começa com <!DOCTYPE html> e <html lang="pt-BR">
  • ☐ charset, viewport e title presentes no head
  • ☐ Exatamente um <main> e um <h1>
  • ☐ Títulos em ordem (h1 → h2 → h3), sem pular nível
  • ☐ Moldura com header / main / footer
  • ☐ section só com tema e título; article só para peça independente
  • ☐ div usada apenas quando nenhuma tag serve
  • ☐ Toda img tem alt; todo input tem label
  • ☐ Link para navegar, button para agir
  • ☐ Indentação consistente, tags fechadas

CSS

  • ☐ Reset e base primeiro; componentes no meio; utilitárias e media queries no fim
  • ☐ Fonte e cor definidas uma vez no body (herança)
  • ☐ Seletores curtos: quase tudo é uma classe só
  • ☐ Sem id no CSS, sem style="" inline, !important só justificado
  • ☐ Nomes por função, minúsculas com hífen, língua única
  • ☐ Valores repetidos viraram variável (--azul)
  • ☐ Mobile-first (min-width)
  • ☐ Nenhum outline: none sem substituto de foco

Teste final (2 minutos)

  1. Reduza a janela até 320px. Nada sai da tela? Sem barra de rolagem horizontal?
  2. Navegue só com a tecla Tab. Dá para ver onde está o foco?
  3. Aumente o zoom do navegador para 200%. O layout aguenta?
  4. Abra o DevTools no elemento mais complexo. Quantas propriedades riscadas? Quanto menos, melhor.

Cola de bolso: perguntas que resolvem 90% das dúvidas

"Qual tag uso?"

Existe uma tag com o significado? Use. Senão, div. (doc 18)

"Meu estilo não aparece"

Seletor acha o elemento? Alguém mais específico? Empate com ordem errada? (docs 13–15)

"Onde declaro a fonte?"

No body. Os filhos herdam. (docs 10–11)

"Qual classe escrevo primeiro?"

Do geral para o específico: base → estrutura → componente → modificador → utilitária. (doc 20)

"Como nomeio?"

O que é, não como parece. Prefixo = dono. (docs 02, 21)

"Flex ou grid?"

Uma dimensão: flex. Duas: grid. (doc 04)
