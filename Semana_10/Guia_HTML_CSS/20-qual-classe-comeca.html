Qual classe começa? A ordem de escrita do CSS

A pergunta clássica: "por onde eu começo o CSS?". A resposta profissional é uma ordem em camadas, do mais geral ao mais específico. É a mesma lógica da cascata: o que vem depois vence os empates, então o mais genérico vem antes.

A escada das 8 camadas

  1. Reset / normalização. Zera diferenças entre navegadores: * { box-sizing: border-box; }, margens do body.
  2. Variáveis (tokens). Cores, fontes, espaços em um só lugar: :root { --azul: #1b4f72; }
  3. Base (tags). body, h1…h6, p, a, img. Aqui entra a herança: fonte, cor, line-height.
  4. Estrutura. .container, .secao. O esqueleto de largura e respiro.
  5. Layout. .grid, .flex, colunas. Como os blocos se organizam.
  6. Componentes. .botao, .card, .menu, .rodape, na ordem em que aparecem na página.
  7. Modificadores e estados. .botao--primario, .is-open. Depois do componente que alteram.
  8. Utilitárias e media queries. .text-center, .hidden e, por último, as media queries que ajustam tudo para telas maiores.

Mapa da ordem num único arquivo

/* 1. RESET */
* { box-sizing: border-box; }
body { margin: 0; }

/* 2. TOKENS */
:root { --azul: #1b4f72; --espaco: 16px; }

/* 3. BASE (tags) */
body { font-family: Arial, sans-serif; line-height: 1.6; color: #263238; }
a { color: inherit; }
img { max-width: 100%; display: block; }

/* 4. ESTRUTURA */
.container { max-width: 1100px; margin: 0 auto; padding: 0 var(--espaco); }
.secao { padding: 64px 0; }

/* 5. LAYOUT */
.grid { display: grid; gap: var(--espaco); grid-template-columns: repeat(auto-fit, minmax(240px, 1fr)); }

/* 6. COMPONENTES */
.cabecalho { ... }
.botao { ... }
.card { ... }
.rodape { ... }

/* 7. MODIFICADORES E ESTADOS */
.botao--primario { ... }
.menu.is-open { ... }

/* 8. UTILITÁRIAS E RESPONSIVO */
.text-center { text-align: center; }
.hidden { display: none; }
@media (min-width: 768px) { ... }

Por que nesta ordem?

CamadaMotivo de vir nessa posição
Reset e base primeiroSão o piso. Qualquer classe precisa vencê-los sem esforço.
Estrutura antes dos componentesQuase todo componente vive dentro de um container.
Modificador depois do componenteMesmo peso 0-0-1-0, vence quem vem por último.
Utilitárias no fimSão a "palavra final" do desenvolvedor.
Media queries no fimMesmo peso que a regra base; precisam vir depois para sobrescrevê-la.

Mobile-first: a base é o celular

As regras fora de media query descrevem o celular. Telas maiores entram por min-width:

.grid { grid-template-columns: 1fr; }              /* celular */
@media (min-width: 768px) {
  .grid { grid-template-columns: repeat(3, 1fr); } /* tablet para cima */
}

E no HTML, qual classe aparece primeiro?

Escreva as classes em ordem de geral → específico. A ordem no atributo class não muda a cascata (quem manda é a ordem no CSS), mas é uma convenção que facilita a leitura:

<button class="botao botao--primario botao--grande mt-3">
         componente  variação      variação   utilitária

Pegadinha: a ordem das classes dentro do class="..." do HTML não importa para quem vence. Quem decide é a posição da regra no arquivo CSS, depois da especificidade.
