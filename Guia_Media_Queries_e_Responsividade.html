Guia de Media Queries e Responsividade

M1S10 — Desenvolvimento Front-End [React] T4 · Do conceito à prática, com exemplos no projeto Bikcraft · Complementa o Guia_Tamanhos_Padrao_Responsivo.html

1. O que é responsividade?

Design responsivo é a técnica de construir uma única página que se adapta ao tamanho da tela em que está sendo exibida (celular, tablet, notebook, TV), em vez de criar um site diferente para cada aparelho.

Analogia: a água. Ela assume o formato do copo, da garrafa ou do balde onde é colocada, mas continua sendo a mesma água. Uma página responsiva é o conteúdo (a água) e o CSS decide o formato do recipiente.

Por que isso importa?

  • Mais de 60% dos acessos à web no Brasil vêm de celular. Uma página que só funciona no computador perde a maior parte do público.
  • Você mantém um só código, e não três sites para atualizar.
  • O Google prioriza sites otimizados para celular (mobile-first indexing).
  • É requisito básico em qualquer vaga de front-end.

Os três pilares da responsividade

PilarO que éComo se faz
1. Meta viewportAvisa ao celular para usar a largura real da tela<meta name="viewport" ...>
2. Layout e mídia fluidosTamanhos relativos, que crescem e encolhem com a tela%, rem, vw, clamp(), Flexbox, max-width:100%
3. Media queriesRegras de CSS que só valem em certos tamanhos de tela@media (min-width: 768px) { ... }

2. Passo 0: o meta viewport

Sem ele, o celular finge ser uma tela de desktop (≈ 980px) e encolhe a página para caber. O resultado: letras minúsculas e nenhuma media query funcionando de verdade. Coloque no <head> de toda página:

<meta name="viewport" content="width=device-width, initial-scale=1.0">
  • width=device-width: a largura da página é a largura real do aparelho.
  • initial-scale=1.0: sem zoom inicial.
Erro nº 1 dos alunos: escrever um CSS responsivo perfeito e esquecer o meta viewport. No DevTools funciona, e no celular de verdade não. Confira sempre.

3. O que é uma media query?

Uma media query (consulta de mídia) é uma pergunta que o CSS faz ao navegador: "a tela tem no mínimo 768px de largura?". Se a resposta for sim, as regras dentro do bloco passam a valer. Se for não, são ignoradas.

3.1 Anatomia

@media (min-width: 768px) {
  .cartao { width: 50%; }      /* estas regras só valem se a tela for ≥ 768px */
  .titulo { font-size: 2.5rem; }
}
ParteSignificado
@mediaPalavra-chave que abre a consulta
(min-width: 768px)A condição: largura da viewport maior ou igual a 768px
{ ... }Regras CSS normais, escritas dentro do bloco

4. Mobile-first: a regra que guia tudo

Mobile-first significa escrever o CSS primeiro para o celular e ir acrescentando regras para telas maiores com min-width.

Mobile-first (recomendado) 
.menu { flex-direction: column; }

@media (min-width: 768px) {
  .menu { flex-direction: row; }
}
O celular usa só a regra base (leve e simples). Telas maiores acrescentam.
Desktop-first (evitar) 
.menu { flex-direction: row; }

@media (max-width: 767px) {
  .menu { flex-direction: column; }
}
O celular precisa desfazer o que o desktop definiu. Mais código e mais bugs.

Por que mobile-first?

  1. Começa pelo mais difícil: uma tela pequena obriga você a decidir o que é realmente importante.
  2. Menos código: o celular (aparelho mais fraco) carrega só as regras base.
  3. Menos "desfazer": você adiciona, e não cancela regras anteriores.
  4. Espelha o mercado: a maior parte do público está no celular.

A cascata cuida do resto

As media queries não substituem o CSS base: elas se somam a ele. A regra que vem depois e tem o mesmo peso de especificidade vence. Por isso, as media queries ficam depois das regras base do mesmo seletor.

.card { padding: 16px; }                     /* 1. base (celular) */

@media (min-width: 768px)  { .card { padding: 24px; } }   /* 2. tablet+ sobrescreve */
@media (min-width: 1024px) { .card { padding: 32px; } }   /* 3. desktop sobrescreve */
Ordem importa: em min-width, escreva do menor para o maior (768 → 1024 → 1440). Se você inverter, a de 768px sobrescreve a de 1024px em telas grandes, porque vem depois e vale também nelas.

5. Onde escrever a media query

5.1 No mesmo arquivo CSS (recomendado)

/* style.css */
.cartao { ... }

@media (min-width: 768px) { ... }

5.2 Em arquivos separados por tela (opcional, projetos grandes)

<link rel="stylesheet" href="base.css">
<link rel="stylesheet" href="tablet.css"  media="(min-width: 768px)">
<link rel="stylesheet" href="desktop.css" media="(min-width: 1024px)">

Para a turma, fique com a opção 5.1 (um arquivo, com blocos @media ao final ou logo abaixo de cada componente).

6. Unidades que tornam o layout fluido

Media queries resolvem os "saltos" de layout. As unidades relativas resolvem a transição suave entre os saltos.

UnidadeRelativa a…ExemploBom para
pxNada (absoluta)border: 1pxBordas, sombras, detalhes finos
%Elemento paiwidth: 50%Larguras de colunas
remFonte da raiz (html, normalmente 16px)font-size: 1.5rem (24px)Fontes e espaçamentos
emFonte do próprio elementopadding: 1emBotões que escalam com o texto; breakpoints
vw / vh1% da largura / altura da telapadding: 5vwBanners e respiros
chLargura do caractere "0"max-width: 65chLimitar linha de texto
frFração do espaço livre (Grid)grid-template-columns: 1fr 1frColunas iguais

6.1 A função clamp() — responsividade sem media query

font-size: clamp(2rem, 5vw, 4rem);
/*              mín   ideal  máx  */

O título nunca é menor que 2rem, nunca é maior que 4rem, e entre um e outro acompanha 5% da largura da tela. Uma linha substitui duas ou três media queries.

6.2 Imagem fluida (obrigatória)

img { max-width: 100%; height: auto; }

max-width: 100% impede a imagem de passar da largura do pai. height: auto mantém a proporção.

7. Layouts que se adaptam quase sozinhos (Flexbox)

Com Flexbox, muitas vezes você resolve a responsividade sem escrever nenhuma media query:

.lista {
  display: flex;
  flex-wrap: wrap;        /* quebra de linha se não couber */
  gap: 16px;
}
.cartao {
  flex: 1 1 280px;        /* cresce, encolhe, base de 280px */
}

Cada card tenta ter 280px. Se não couberem dois lado a lado, o Flexbox quebra a linha automaticamente. Em 375px há 1 por linha, em 768px há 2, em 1200px há 3 ou 4. Sem media query.

Regra prática: primeiro tente resolver com unidades fluidas + Flexbox (wrap, flex). Use media queries quando o layout mudar de estrutura (coluna vira linha, menu muda de formato, muda o número de colunas de forma controlada).

8. Passo a passo: transformando uma página em responsiva

Esboce no Excalidraw. Desenhe 3 versões da página (celular, tablet, desktop). Decida o que muda de um para o outro.
Meta viewport no HTML. Uma linha no <head>.
Escreva o CSS base para o celular. Coluna única, fontes de 16px, padding de 16px, imagens com max-width:100%. Sem nenhuma media query ainda.
Teste em 320px, 360px e 390px no DevTools. Nada pode gerar rolagem horizontal.
Alargue a janela devagar. No ponto em que o layout começar a ficar estranho (texto muito esticado, muito espaço vazio), anote a largura. É o seu breakpoint.
Adicione @media (min-width: …) com só o que muda: número de colunas, direção do menu, tamanho de título, paddings.
Repita para o próximo breakpoint (1024px) e teste tudo de novo, do menor ao maior.

9. Exemplo completo: o cabeçalho do Bikcraft

HTML

<header class="cabecalho">
  <span class="logo">bikcraft</span>
  <nav class="menu">
    <a href="#">Bicicletas</a>
    <a href="#">Seguros</a>
    <a href="#">Contato</a>
  </nav>
</header>

CSS mobile-first

/* ===== BASE: celular ===== */
.cabecalho {
  display: flex;
  flex-direction: column;   /* logo em cima, menu embaixo */
  align-items: center;
  gap: 12px;
  padding: 16px;
}
.menu { display: flex; gap: 8px; }
.menu a { padding: 12px; }      /* área de toque ≥ 44px */

/* ===== TABLET: a partir de 768px ===== */
@media (min-width: 768px) {
  .cabecalho {
    flex-direction: row;          /* logo e menu na mesma linha */
    justify-content: space-between;
    padding: 16px 32px;
  }
}

/* ===== DESKTOP: a partir de 1024px ===== */
@media (min-width: 1024px) {
  .cabecalho { padding: 16px 100px; }
  .menu { gap: 24px; }
}

Repare que cada bloco só declara o que mudou. Nada é repetido, nada é desfeito.

10. Exemplo: grade de cards em 1, 2 e 3 colunas

.grade {
  display: grid;
  grid-template-columns: 1fr;      /* celular: 1 coluna */
  gap: 16px;
}
@media (min-width: 768px)  { .grade { grid-template-columns: repeat(2, 1fr); gap: 24px; } }
@media (min-width: 1024px) { .grade { grid-template-columns: repeat(3, 1fr); gap: 32px; } }

Versão com Flexbox e sem media query, para comparar:

.grade { display:flex; flex-wrap:wrap; gap:16px; }
.grade > * { flex: 1 1 280px; }

12. Ferramentas de trabalho

  • Excalidraw (excalidraw.com): esboço de layout em modo "rascunho" antes de codar. Veja o roteiro de uso no enunciado do exercício do dia 29/09.
  • Chrome DevTools, modo dispositivo (F12 → Ctrl+Shift+M): simular celulares, tablets e larguras livres.
  • Live Server (VS Code): recarrega a página a cada salvamento.
  • Google Fonts: tipografia profissional (Poppins, Inter, Roboto), como no guia de tamanhos padrão.

13. Resumo em 8 regras

  1. Toda página começa com o meta viewport.
  2. Escreva o CSS base para o celular.
  3. Use @media (min-width: …) para acrescentar regras em telas maiores.
  4. Ordene as media queries do menor para o maior, depois das regras base.
  5. Prefira unidades relativas (rem, %, vw, clamp()).
  6. Imagens: max-width:100%; height:auto;
  7. Use poucos breakpoints (768px e 1024px resolvem quase tudo) e escolha-os pelo conteúdo.
  8. Teste no DevTools do menor ao maior, sempre sem rolagem horizontal.
